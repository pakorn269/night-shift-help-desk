```text
Use Kiro Spec mode to generate your own requirements, design and task list under .kiro/specs/. Keep .kiro/ visible in Git; do not represent the planning docs as Kiro-generated. Then implement the first slice in this folder.

Use Vite, Vanilla TypeScript, HTML/CSS, and npm. Implement only the 03:00 ticket with the impossible 03:07 audit entry, two decisions with distinct endings, and replay. Keep the player-facing copy easy to change. No real employer data or branding, backend, login, paid services, or public deployment. Do not build case 2 or case 3.

Run the production build, verify both endings and replay, and report the local run command, the actual tests performed, and any unverified checks. Do not create a remote, push, or publish.
```
